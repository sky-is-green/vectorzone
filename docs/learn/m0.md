# M0 — Hello, vector: learning notes

*What this milestone taught, what we decided, and how we verified it.*

## three.js concepts used

- **Renderer** (`WebGLRenderer`): owns the canvas and the GL context. `setPixelRatio` (capped at 2) keeps retina crisp without burning fill rate; `setSize` on resize. `renderer.info.render.calls` is the draw-call counter our I6 gate reads.
- **Scene**: the container everything lives in. `scene.background = black` is the void.
- **Camera** (`PerspectiveCamera`): fov / aspect / near / far. Aspect must be updated on resize followed by `updateProjectionMatrix()`, or the image stretches.
- **Geometry vs Material vs Object3D**: `BoxGeometry` holds vertices; `EdgesGeometry` derives only the hard edges (no triangulation diagonals — that's why the cube reads as a clean wireframe); `LineBasicMaterial` holds the phosphor color; `LineSegments` is the object that draws pairs of vertices as lines. The mesh/material/object split is the core three.js idea: *shape*, *appearance*, *placement* are separate things.
- **No lights**: `LineBasicMaterial` is unlit. The entire game will stay unlit (black faces + glowing edges), which is why the vector look is so cheap.
- **The render loop**: `requestAnimationFrame` drives rendering at display rate; the **sim** inside it advances in fixed 1/60 s steps via an accumulator (invariant I2). Render time is interpolated (`tick + accumulator/TICK_DT`) so motion is smooth at 83 Hz, 120 Hz, anything — while the sim stays deterministic.
- **Delta-time clamping**: `dt = min(frameGap, 0.25)` prevents a spiral of death after tab switches.

## Sim concepts used

- **Seeded RNG (mulberry32)**: all randomness flows through `createRng(seed)`. Same seed → same sequence on every machine. This is the foundation of determinism tests, client prediction, and host-authoritative multiplayer.
- **Determinism gate**: `hashWorld` (FNV-1a over seed/tick/probe/rng-state) lets a test assert *same seed + same ticks → identical state*. Every future sim feature inherits this pattern.
- **Sim purity**: `packages/sim` has no DOM lib in its tsconfig and a grep gate (`check:sim`) — it cannot accidentally depend on three.js or the browser. It runs identically in Node (tests, future server) and the browser.

## Decisions made

- Seed constant `0xb477e2` for the M0 demo world (arbitrary, recorded).
- Stats overlay is plain DOM (monospace green, top-left) — the future HUD band grows from this idea but radar/score will be canvas 2D per RADAR.md.
- Vite `base: './'` so the static build works under GitHub Pages / itch.io subpaths.
- `npm run build` typechecks the client before bundling; `check:sim` typechecks the sim with **no DOM lib**, so purity is enforced by the compiler too.
